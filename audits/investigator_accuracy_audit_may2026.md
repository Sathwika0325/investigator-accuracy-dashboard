- **Strongest on config/data and precise DB-level diagnoses.** The Investigator excelled where the answer was a concrete record, SQL update, or configuration link — inventory adjustments (80578, 80666, 80831), user/admin field updates (80196), country/dropdown config (80142, 80313, 80716), and NOT-NULL migration constraints (80304, 95%). These matched the applied fixes almost exactly.

- **Excellent on well-scoped code root-cause tickets that dev later confirmed.** The city-name validation gap (80421, 95%), the visible_to_customer migration-ahead-of-code (80304, 95%), the Braintree settlement failure (80293), the file-name UI truncation (80802), the admin-approval-hold status bug (80792), the ship-date re-evaluation gap (80913), the raw-state-id email regression (80873), and the Semrush WAF block (80469, 95%) were all confirmed by developer investigations — several naming the exact class/PR the AI predicted.

- **Consistent, correct triage of non-technical and "no bug" tickets.** QR validation tasks, access requests, "Collaterate is down" (cache), build-review notifications, and template edit requests were correctly classified and routed, keeping noise low.

- **The six inaccurate cases share a pattern: confident single root-cause claims that dev later disproved.** 80034, 80322 (inventory vs. billing-address/REST config), 80364 (blamed a bulk-hide script; dev said a different DIGITAL-products issue), 80526 (issue flag vs. an Orika mapping 500), 80712 (stale reconciliation vs. a cart-redemption plugin bug), and 80945 (pathValidation theory vs. a permissions fix). In several of these the Investigator also asserted "no application errors found" when a code-level error was in fact present (notably 80526).

- **Partial scores cluster around plausible-but-unconfirmed theories and cases the AI couldn't fully reach.** BOM Builder silent failure (80237), reorder file duplication, weight fallback (72920), the DC auto-assign investigation that hit max iterations (80568), and the HUB PID request that turned out to be Pace kitting supplies (80897) were directionally useful but either unverified or contained a sub-hypothesis dev corrected.

- **Attachment blindness is a recurring limitation.** On 80712 the Investigator could not open the PowerPoint describing the bug and defaulted to a broad system scan, landing on the wrong cause. Where the symptom lives only in an image/PPT/PDF, accuracy drops.

- **Actionable takeaway:** The Investigator is highly reliable for data/config lookups and well-instrumented code paths, and its comments are increasingly cited directly by agents and developers (a stakeholder on 80716 explicitly asked the team to keep making AI comments accurate). The main improvement area is hedging single root-cause claims when logs/reproduction are incomplete — especially avoiding "no errors found" assertions and flagging when a conclusion depends on an unreadable attachment.
